# 历史试答与本版证据

下列三段出自 2026-11-18 的 Claude Code 本机运行，模型记录为 `claude-opus-5-5`。4.0.0 引入真实 harness、持久缓存路径和新的计分单位。旧版错误可用于说明选择测试的原因，本版的失败发生率和区分度仍待实测。摘录及原测试观察保存在 `tests/assets/history-v3.md`。SQLite 模型身份是本版新加入的考点，尚缺本版真实答卷取证。

* **FM1，批调度未保留租户工作边界。** 旧版答卷为缓存条目加入了租户信息，但批划分只使用模型、适配器和温度。对两个来自不同租户的相同 prompt，实测两行合在一个 forward。3.x 以一次调度判失败；4.0.0 允许把两份独立工作放进同一次调用，只检查一个租户的已算结果或前缀是否替另一个租户完成工作。这份旧答卷只能解释测试来源。
* **FM2，前缀缓存改变了公开容器的长度。** 旧版另一份答卷分别为 `True` 和 `1` 调用了模型，但 `KVCache.__len__` 把独立的前缀条目也计作完整序列。缓存里有 2 个请求的结果，答卷报告 4。
* **FM3，把配置字段的整数约束用于 prompt。** 旧版答卷对生成长度等配置拒绝布尔值，在验证 prompt 时复用了相同谓词，导致旧调用方传 `True` token 时抛异常。
